Tu primera práctica con Mercado Pago

Actualización para la tienda Elizabet, alojada en Netlify. Conecta el carrito con Checkout Pro mediante la API de Preferencias, usando únicamente una cuenta vendedora de prueba. Incluye también la actualización de stock por talle entregada antes.

Esta versión es de práctica. El enlace para probar pagos está disponible desde el panel de administración. Las pruebas se guardan aparte: no crean pedidos de venta ni descuentan stock. El carrito habitual sigue funcionando igual para las visitas de la tienda.

1. La variable que ya guardaste

En Netlify → proyecto elicdu → Project configuration → Environment variables:

  • Key: MERCADOPAGO_ACCESS_TOKEN.
  • Marcada como Contains secret values.
  • El valor de Production es el Access Token copiado desde Credenciales de prueba de la aplicación cduDIGITAL Pruebas.
  • Los demás contextos pueden quedar vacíos para esta práctica.

Production es el contexto de la web publicada de Netlify. No transforma el token de prueba en uno real. Tanto un token de prueba como uno real pueden empezar con APP_USR: elegilo por la sección de donde lo copiás. No pegues claves en GitHub, en los archivos ni en un chat. El backend verifica que el vendedor de Mercado Pago tenga la etiqueta de usuario de prueba y pertenezca a Argentina; rechaza un vendedor real.

2. Subir la actualización a GitHub

  1. Desde la computadora, descargá Elizabet_Mercado_Pago_Practica.zip.
  2. Extraé el ZIP por completo. En Windows: botón derecho → Extraer todo. Abrí la carpeta extraída; no arrastres desde el interior del ZIP.
  3. Entrá a tu repositorio elizabet-tienda. En la raíz, donde están package.json y netlify.toml, elegí Add file → Upload files.
  4. Arrastrá completas las cinco carpetas del ZIP: lib, netlify, public, scripts y tests. Deben conservar sus nombres y sus archivos adentro. No subas los archivos sueltos ni una carpeta extra que envuelva a esas cinco.
  5. Podés subir también esta guía en la raíz. Tocá Commit changes.
  6. Netlify compila y publica automáticamente. En Deploys esperá que el nuevo despliegue diga Published.

El ZIP contiene únicamente archivos nuevos o actualizados, sin dependencias, fotos adicionales ni credenciales. No borres los demás archivos del repositorio. Los productos, fotos subidas, configuración y pedidos guardados en Netlify Blobs se conservan; el cambio de stock migra los productos que ya cargaste.

3. Abrir la práctica desde la tienda

  1. Abrí elicdu.netlify.app/admin e ingresá con el usuario y la contraseña de tu panel.
  2. En el menú del panel, debajo de las secciones, tocá Probar pagos ↗. Se abre la tienda con el aviso PRÁCTICA DE MERCADO PAGO.
  3. Elegí una prenda con stock, el talle y la cantidad; agregala al carrito. Para esta práctica también se permiten las prendas de muestra.
  4. Abrí el carrito → Probar pago con Mercado Pago → Preparar pago de prueba.
  5. Usá Copiar enlace para incógnito. Abrí una pestaña de incógnito en Chrome y pegá el enlace. Así evitás usar tu sesión personal de Mercado Pago.

No hace falta activar pedidos reales en Mi marca para probar este botón. Los precios se consultan en el servidor; el navegador no decide cuánto se paga. No se necesita Public Key para este flujo de redirección.

4. Usar una cuenta compradora de prueba

En tu aplicación de Mercado Pago Developers, abrí Cuentas de prueba y elegí una cuenta de tipo Comprador, país Argentina. Si falta, creala. Usá su usuario y contraseña para ingresar al checkout en incógnito. Debe ser distinta de la cuenta vendedora mostrada en Credenciales de prueba. No uses tu cuenta personal.

Los pasos y datos actualizados están en la guía oficial de compras de prueba. Datos consultados el 26/10/2026:

5. Verificar el resultado

  1. Al terminar, tocá Volver al sitio en Mercado Pago. Se abre la pantalla de resultado de la práctica.
  2. Si abriste el enlace en incógnito, tocá Ingresar a mi panel e iniciá sesión en el panel de Elizabet dentro de esa misma ventana de incógnito. Volvé a la pestaña del resultado.
  3. Tocá Verificar en Mercado Pago. Si el número de pago está vacío, copiá el número del pago que muestra Mercado Pago al finalizar.
  4. La tienda consulta a Mercado Pago y muestra aprobado, pendiente o rechazado. No confía en el estado que venga escrito en la URL. No cambia las unidades de stock.

Las verificaciones se realizan al tocar el botón; todavía no hay notificaciones automáticas de pagos. Los intentos de práctica quedan fuera de la sección Pedidos. Si la sesión de administrador vence, ingresá otra vez.

6. Stock de los pedidos habituales

La actualización incluye el control de stock. Los pedidos habituales quedan Nuevos y todavía no reservan unidades. Al cambiar un pedido a En preparación o Entregado, se descuenta una sola vez cada talle. Pasarlo de En preparación a Entregado no vuelve a descontar. Cancelado repone una sola vez las unidades descontadas: usalo únicamente si las prendas quedan disponibles para volver a vender. Las pruebas de Mercado Pago están separadas de este proceso.

Actualizá el panel para ver cambios de otro dispositivo. Ajustá manualmente el stock por ventas fuera de la web. Los pedidos confirmados antes del control automático conservan su manejo manual. No vuelvas a desplegar el código anterior de stock después de usar esta versión, porque leería cantidades antiguas.

Antes de recibir dinero real

Esta práctica bloquea los vendedores reales. Para lanzar los cobros de la marca hace falta una actualización posterior que vincule pagos reales con pedidos e inventario, contemple la reserva de stock, verifique notificaciones de Mercado Pago y controle reintentos, pagos pendientes, cancelaciones y reembolsos. Cambiar únicamente el token no habilita cobros reales en esta versión.
